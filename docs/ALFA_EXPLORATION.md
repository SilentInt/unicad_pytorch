# ALFA 无人机异常检测方案探索

## 1. 数据集概况

**ALFA (AIR Lab Fault Detection Dataset)**: Carbon Z 固定翼无人机飞行数据，Pixhawk 飞控，2018年采集于匹兹堡。

| 维度 | 值 |
|---|---|
| 总序列数 | 47 (46 可用于监督学习) |
| 纯正常序列 | 10 条 (`no_failure`) |
| 含故障序列 | 36 条 |
| 未知标签 | 1 条 (`no_ground_truth`) |
| 总飞行时间 | ~82 分钟 |
| 采集频率 | 0.7 Hz ~ 50 Hz (各topic不同) |

### 1.1 故障类型分布

| 故障类型 | 序列数 | 正常帧 | 故障帧 | 故障帧占比 |
|---|---|---|---|---|
| engine_failure | 7 | 6,567 | 1,034 | 13.6% |
| engine_failure_with_emr_traj | 16 | 16,258 | 2,583 | 13.7% |
| elevator_failure | 2 | 1,814 | 233 | 11.4% |
| aileron_failure (含组合) | 7 | 6,312 | 3,223 | 33.8% |
| rudder_failure | 4 | 2,839 | 686 | 19.5% |
| no_failure | 10 | 5,578 | 0 | 0% |
| **合计** | **46** | **39,368** | **7,759** | **16.5%** |

### 1.2 标注特性

- **唯一可用标签**: `failure_status-*.csv` 标记故障激活区间，无 `field.data=0` 行（文件仅含故障持续期间的条目）
- **无飞行状态标注**: `mavros-state` 中 `field.mode` 始终为 `GUIDED`，无平飞/转弯/爬升等标签
- **故障 onset 时间精确**: 第一行数据即故障起始时刻
- **故障占比**: 序列层面故障占 78%，帧层面正常帧占 84%

### 1.3 关键传感器通道 (22 维, 对齐至 10 Hz)

### 1.4 采样率与对齐策略

统一重采样至 10 Hz（线性插值）：
- 10 Hz 信号 (IMU): 直接使用
- 19 Hz 信号 (nav_info): 降采样
- 4 Hz 信号 (position): 升采样
- 2.9 Hz 信号 (rc_out): 升采样
- `%time` 列为纳秒时间戳，以它为主时间轴

## 2. 核心发现：逐帧特征无法有效区分正常与故障

### 2.1 逐帧特征可分性 (KS 检验)

| 可分性等级 | 特征数 | 占比 |
|---|---|---|
| 高度可分 (KS > 0.5) | **0** | 0% |
| 中等可分 (0.2 < KS < 0.5) | 10 | 45% |
| 弱可分 (KS < 0.2) | 12 | 55% |

没有任何单帧特征能高度区分正常与故障。角速度、加速度等 IMU 核心信号全部弱可分。

### 2.2 原因分析

- 正常飞行本身变异性大（转弯时角速度与舵面故障相似）
- 故障多为渐变开始（油门缓慢漂移而非瞬间归零）
- 47.3% 的故障帧落入正常帧 95% 分布范围内

### 2.3 各故障类型与正常数据的平均可分性

| 故障类型 | 平均 KS 统计量 | 说明 |
|---|---|---|
| rudder | 0.377 | 最易区分 |
| engine | 0.289 | 较易区分 |
| elevator | 0.275 | 中等 |
| aileron | 0.143 | **最难区分** |

副翼故障最难检测：正常转弯也有大角度副翼偏转，模式高度重叠。

## 4. 为什么"预测"远优于"重建"

### 4.1 本质区别

| 方法 | 核心问题 | 对稳态故障的响应 |
|---|---|---|
| 重建型 (AE, 窗口统计) | "这个模式我见过吗？" | 油门锁死在1100后AE学会重建 → 漏检 |
| 预测型 (MLP predictor) | "下一步应该发生什么？" | 预测器基于正常动力学预测油门应回到1400 → 误差持续高 |

### 4.2 预测误差的物理含义

预测误差 e_t = (x_t - x̂_t)² 是**22维向量**，每维代表一个传感器通道的"不可预测程度"。不同故障类型激活不同的通道组合——形成**故障指纹**：

| 通道 | normal | engine | elevator | aileron | rudder |
|---|---|---|---|---|---|
| rc_ch2 (油门) | 0.008 | 0.047 (5.6×) | 0.013 | **2.015 (240×)** | 233.6 (27800×) |
| rc_ch3 (偏航) | 0.008 | 0.051 (6.1×) | 0.020 | **1.256 (150×)** | 134.3 (16038×) |
| rc_ch4 (左副翼) | 0.008 | 0.043 (5.1×) | 0.023 | **1.922 (229×)** | 131.9 (15727×) |
| nav_airspeed_err | 0.016 | 0.116 (7.1×) | **1.994 (122×)** | 0.029 | 4.337 (266×) |
| nav_pitch_err | 0.062 | 0.119 (1.9×) | 0.027 (0.4×) | **0.330 (5.3×)** | 6.733 (108×) |
| acc_z | 0.003 | **0.168 (50×)** | 0.012 | 0.013 | 0.186 (55×) |
| rc_ch1 (俯仰) | 0.002 | **0.137 (62×)** | 0.013 | 0.013 | 0.116 (52×) |
| gyro_x | 0.083 | 0.365 (4.4×) | 0.147 | 0.349 (4.2×) | **10.866 (131×)** |

**诊断规律**：
- **发动机**: acc_z↑ + rc_ch1↑ + throttle↑ (推力丧失 → 俯仰补偿 → 油门异常)
- **升降舵**: nav_airspeed_err↑ + pitch 通道异常
- **副翼**: rc_ch2/3/4 同时↑ (副翼通道冻结/异常)
- **方向舵**: gyro/acc 全面爆发 (偏航失控 → 剧烈振荡)

### 4.3 故障类型分类 (基于预测误差指纹)

KNN (k=5) 5-fold 交叉验证：

| 故障类型 | Precision | Recall | F1 | Support |
|---|---|---|---|---|
| engine | 0.898 | 0.909 | 0.903 | 3603 |
| elevator | 0.661 | 0.519 | 0.582 | 233 |
| aileron | 0.910 | 0.911 | 0.910 | 3489 |
| rudder | 1.000 | 0.995 | 0.998 | 412 |
| **加权平均** | **0.901** | **0.903** | **0.902** | **7737** |

## 5. 训练策略分析

### 5.1 方案对比

#### 方案 A: 正常数据训练 Galaxy (之前推荐)

```
训练数据: 仅正常帧的预测误差
Galaxy: 学会正常误差模式 → 任何偏离 = 异常
```

- 优点: AE 只见过正常模式 → 故障重建误差大 → 检测灵敏
- 缺点: 无法区分故障类型（所有故障都只是"异常"）

#### 方案 B: 全部数据训练 Galaxy (用户最初提议)

```
训练数据: 全部帧(含故障)的预测误差 → AE预训练 → EM排除异常
```

- 问题: AE 学会重建故障模式 → 故障帧重建误差↓ → 漏检
- 实测: AUC 从 0.900 降至 0.868

#### 方案 C: 正常训练检测 + 误差指纹分类 (解耦方案)

```
阶段1: Galaxy(normal) → 异常/正常 判定
阶段2: 预测误差向量 → KNN → 故障类型分类
```

- 优点: 检测和分类解耦，互不干扰
- 缺点: 两个独立模型，未利用误差通道间关联

### 5.2 新方案: 预测器(normal) → 逐通道正则化 → Encoder(全部数据) → 聚类

```
传感器数据 → 预测器(normal训练) → 原始预测误差(22D)
    → 逐通道正则化(消除量纲差异) → 正则化误差(22D)
    → Encoder(全部数据训练, 学习通道关联) → 潜在表示(16D)
    → 聚类 → 正常簇 / 各故障类型簇
```

**核心思路变化**:
- Encoder 在全部数据上训练，角色是**特征提取器**而非异常检测器
- AE 能重建故障 ≠ 故障和正常在潜在空间混在一起
- 编码器可以把正常映射到一个区域，不同故障映射到不同区域
- 解码器都能重建，但**潜在空间可分**

**逐通道正则化的必要性**:
- 无正则化: 方向舵误差 ~100× 正常，副翼误差 ~5× 正常 → 方向舵主导编码器
- 正则化后: 每通道误差量纲统一 → 编码器关注"哪些通道同时异常"的**模式**而非幅度

**聚类选择 — Kernel KMeans**:
- 线性 KMeans 假设簇是凸形，但正则化误差空间中故障簇可能是非凸的
- RBF kernel 可将非线性可分数据映射到高维空间使其线性可分
- 适合"不同故障类型在不同通道组合上异常"的非线性结构

## 6. 已验证 vs 待验证

### 6.1 已验证结论

1. **逐帧原始特征无法有效检测故障** (47.3% 故障帧与正常重叠)
2. **预测误差是最有效的时序特征** (AUC 0.900 vs 原始帧 0.735)
3. **预测误差携带故障指纹** (22 维误差向量可直接分类，准确率 90.3%)
4. **正常帧训练 Galaxy 优于混合训练** (AUC 0.900 vs 0.868)
5. **AR 残差不适用** (稳态故障残差趋零, AUC 0.556)
6. **1D Conv AE 表现差** (局部模式不够判别性, AUC 0.678)
7. **MLP 预测器优于 AE 重建** (预测捕捉因果，重建只匹配模式)

### 6.2 待验证

1. **Encoder(全部数据) + Kernel KMeans 的检测+分类效果**
   - Encoder 是否能在潜在空间中分离正常和不同故障类型？
   - Kernel KMeans (RBF) 是否比线性 KMeans 更好地捕捉故障簇结构？
2. **不同历史窗口长度对性能的影响**
3. **按日期划分 train/val/test 的泛化性能**
4. **实时推理延迟在机载硬件上的实测**

## 7. 实时部署考量

### 7.1 推理流水线

```
每帧 (10Hz):
1. 更新环形缓冲区 (保留最近20帧)                    O(1)
2. 展平送入预测器 (220→22 MLP)                      <0.1ms
3. 计算预测误差 (22维逐通道平方差)                   <0.01ms
4. 逐通道正则化 (减均值除标准差)                     <0.01ms
5. Encoder前向传播 (22→64→16 MLP)                   <0.1ms
6. Kernel KMeans 距离计算 (到各簇中心)               <0.5ms
7. 输出: 异常分数 + 最可能故障类型                    —
   总延迟: <1ms/帧 (预算 100ms@10Hz)
```

### 7.2 模型参数量

| 组件 | 参数量 | 模型大小 |
|---|---|---|
| 预测器 MLP | ~60K | ~240 KB |
| Encoder | ~2K | ~8 KB |
| 聚类中心 (k=15) | 15×16=240 | ~1 KB |
| **总计** | **~62K** | **~250 KB** |

完全满足 Jetson Nano / Jetson Orin Nano 级机载电脑的内存和算力约束。
